# 阶段 7 评审问题修复执行方案

## 1. 文档目的

本文用于修复从 commit `7b849af32ec638726d65ecdd6972c50df1337090` 开始实现的阶段 7。当前代码已经建立通用 `SceneAsset`、glTF 静态网格导入、多 BLAS/TLAS、刚体实例更新、纹理上传和 GGX PBR 主路径，但代码评审发现仍有会导致设备不稳定、动画错误或合法 glTF 静默渲染错误的问题。

## 4. 修复后的数据契约

### 4.1 动画组和 pivot

当前的 `animated_root_instances: Vec<usize>` 只能表达“哪些实例动”，不能表达“围绕哪里动”。推荐改成显式动画组：

```rust
pub struct RigidAnimationGroup {
    pub instance_indices: Vec<usize>,
    pub pivot_world: [f32; 3],
}

pub struct SceneAsset {
    // 其他字段保持不变
    pub rigid_animation_groups: Vec<RigidAnimationGroup>,
}
```

要求：

- glTF 导入完成 placement 后，根据导入模型的 world AABB 保存 pivot；绕 Y 轴时 pivot 的 Y 值不影响轨迹，但仍应保存完整中心以避免契约含糊。
- `SceneAsset::append` 必须偏移组内的 instance index，不改变已经处于最终场景坐标中的 pivot。
- 动画矩阵使用绝对时间，禁止逐帧累加角度：

```text
current_world = T(pivot) * R_y(absolute_time) * T(-pivot) * base_world
```

- 同一动画组的所有 node-primitive instance 使用同一个 group transform，保持节点层级和实例间相对距离。
- `current -> previous` 仍只发生在命令列表提交并成功 Signal 后。

如果不改公共结构，也可以保存等价的 `animation_from_base` 矩阵，但必须通过测试证明模型中心不会随旋转角度产生圆周位移。不得仅调整乘法顺序而没有 pivot 回归测试。

### 4.2 纹理 binding 和 sampler

`MaterialAsset` 的纹理字段不能继续只保存 source image index。推荐契约：

```rust
pub struct TextureBindingAsset {
    pub image_index: usize,
    pub sampler_index: usize,
    pub texcoord_set: u32,
}
```

`SceneAsset` 增加去重后的 sampler 列表；`SceneAsset::append`、`validate` 和 GPU packing 必须同时处理 image/sampler offset 与越界。

本阶段只上传 `TEXCOORD_0`。因此：

- `texCoord` 缺省值 0 正常支持。
- 任一被使用的 base-color、metallic-roughness、normal 或 emissive binding 使用 `texCoord != 0` 时，返回包含材质、纹理角色和 texCoord 的明确错误。
- 材质引用纹理而 primitive 缺少对应 `TEXCOORD_0` 时明确报错，不得把整张 primitive 固定采样 `[0, 0]`。
- primitive 没有 UV 且材质没有纹理时仍可使用 factor 正常渲染。

sampler 必须保留 glTF 的 U/V 独立 wrap 和 min/mag filter：

```rust
pub struct SamplerKey {
    pub min_filter: FilterMode,
    pub mag_filter: FilterMode,
    pub wrap_u: WrapMode,
    pub wrap_v: WrapMode,
}
```

- `wrapS`/`wrapT` 分别映射 Repeat、ClampToEdge、MirroredRepeat。
- `magFilter` 映射 nearest/linear。
- `minFilter` 的 mip 变体在本阶段按其基础 min filter 映射；Shader 仍显式 `SampleLevel(..., 0)`，因为当前没有 mip 和 ray differential。
- 缺省 sampler 使用 repeat U/V 和确定性的 linear min/mag，并在代码注释中说明这是本阶段对 glTF auto filtering 的选择。
- 不得把 U/V 不同 wrap 的 sampler 合并成一个近似 sampler。

建议使用 shader-visible sampler descriptor heap：

- 对 `SamplerKey` 去重后创建 sampler descriptors。
- 根签名增加 bounded sampler descriptor table。
- `SetDescriptorHeaps` 同时绑定现有 CBV/SRV/UAV heap 和 sampler heap。
- HLSL 使用 bounded `SamplerState MaterialSamplers[MAX_MATERIAL_SAMPLERS]`，动态索引也使用 `NonUniformResourceIndex`。
- sampler 数量设置明确上限并在 CPU 侧拒绝越界；不要依赖 HLSL 掩码把错误 index 静默折回合法范围。

`GpuMaterial` 的四个 `texture_and_sampler` 字段可以继续使用 `u32`，但必须定义 Rust/HLSL 一致的位布局。例如：

```text
bits  0..6   texture view index，最多 128 个
bits  7..12  sampler index，最多 64 个
bits 13..31  保留且必须为 0
```

pack/unpack 必须使用共享语义常量和单元测试；CPU 创建场景时先做真实上限检查，Shader 不得仅靠 `& 0x7F` 隐藏越界。

### 4.3 单双面和 front-face

每个 BLAS 对应单一 primitive，每个 TLAS instance 也对应单一材质，因此可在 instance desc 中表达双面语义：

- 普通 primary/bounce/shadow ray 启用 back-face culling。
- glTF `doubleSided=true` 的 instance 设置 `D3D12_RAYTRACING_INSTANCE_FLAG_TRIANGLE_CULL_DISABLE`。
- legacy dielectric 必须允许从介质内部命中退出面，不能因单面剔除破坏折射；可将其视为强制双面。
- 坐标系转换后的 front winding 必须通过最小三角形测试确定，再正确设置 `TRIANGLE_FRONT_COUNTERCLOCKWISE`，不能凭感觉选择。
- HLSL 使用 DXR `HitKind()` 判定 front/back，不能使用插值 shading normal 与 ray 的点积替代几何朝向；smooth normal 在轮廓附近可能与几何面朝向不同。
- double-sided 的背面在光照前翻转 shading normal；single-sided 背面不应进入 closest-hit。

### 4.4 降噪信号不变量

阶段 6 的最终合成是：

```text
final = filtered_diffuse * gbuffer_albedo + filtered_unmodulated
```

因此修复后必须满足：

- `RawDiffuse` 只包含允许按 base color 解调/重调制的 diffuse 信号。
- specular 和 emissive 都属于不按 base color 重调制的信号。可以保留现有 `RawSpecular` 资源，但代码和文档应把其语义明确为 unmodulated signal；不要求为了改名产生大量无意义 diff。
- base color 为 `[0,0,0]` 的 emissive 表面在最终视图仍显示 emissive factor/texture。
- first-bounce 使用 mixture PDF 采样方向后，分别计算：

```text
diffuse_contribution  = f_diffuse  * abs(N·L) / mixture_pdf * child_radiance
specular_contribution = f_specular * abs(N·L) / mixture_pdf * child_radiance
```

- 不能因为本次方向由 cosine proposal 或 GGX proposal 产生，就把 `(f_diffuse + f_specular)` 整体塞进一个信号。
- total radiance 必须等于 direct diffuse、direct specular、emissive 和两个间接分量之和；信号拆分不能改变总路径估计。
- metallic=1 时 first-bounce diffuse 分量应为 0 或浮点误差范围内接近 0，与采样 proposal 无关。

- F1 遍历全部调试视图。
- resize、最小化/恢复。
- 1280×720、1600×900，以及屏幕允许时的 1920×1080。

记录 Total、AS、Path Trace、Temporal、À-Trous 时间。若 `Total` 不包含 AS，文档中必须明确说明，不能把二者当成同一口径。

## 6. Commit 和执行规则

推荐顺序：

1. `fix(stage7-dxr): 修正 TLAS update scratch 和静态更新`
2. `fix(stage7-motion): 围绕导入模型 pivot 更新实例`
3. `fix(stage7-gltf): 保留纹理 sampler 并验证 UV 集`
4. `fix(stage7-texture): 绑定 sampler heap 并修正灰度 alpha`
5. `fix(stage7-material): 实现 glTF 单双面剔除`
6. `fix(stage7-pbr): 修正自发光和 lobe 降噪信号`
7. `test(stage7): 补齐 glTF 修复回归和 RTX 4060 验收`

允许继续拆分，但遵守以下规则：

- 每个 commit 都必须编译，不能提交“下一个 commit 才能修好”的中间破损状态。
- 每个 commit 只包含一个可描述、可回滚的主题。
- 不使用 `git reset --hard`、`git checkout --` 覆盖用户改动。
- 不删除或放宽现有测试来让修复通过。
- 不使用 `#![allow(...)]`、扩大 unsafe 或 Shader 掩码来隐藏越界。
- 不顺手进行阶段 8 优化或无关重构。
- 提交前检查 `git diff --check` 和 `git status --short`，只 stage 本工作包文件。
- 如果缺少本地公开 PBR 资产，不联网偷偷下载；先完成可离线工作并明确报告最终手工验收仍未完成。

## 7. Luna 最终交付清单

Luna 完成后必须给出：

- 实际创建的 commit hash 和每个 commit 的主题。
- R1–R8 分别在哪些文件中修复。
- 自动化命令的真实结果，不使用“应该通过”。
- RTX 4060 Laptop 真机运行了哪些矩阵、各运行多久、有无 GPU validation error。
- sampler/UV、双面、黑色 emissive、动画 pivot 的可观察验证结果。
- 尚未完成或无法验证的项目；存在未完成项时不得宣布阶段 7 完成。
- 最终 `git status --short`，并说明是否存在用户原有改动。
