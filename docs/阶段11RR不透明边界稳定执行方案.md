# 阶段 11：RR 不透明几何边界稳定执行方案

日期：2026-08-13

计划基线：`7e1d53d fix(stage11): stabilize visible RR light edges`

目标硬件：NVIDIA GeForce RTX 4060 Laptop GPU

执行方式：Luna 按独立提交实现，Codex review、修复和验收

## 1. 结论

本轮只修复 DLSS Ray Reconstruction（RR）下不透明主表面接缝的静态抽动，例如 Cornell
Box 左/右墙与后墙的红灰、绿灰接缝。采用下面的最小商业引擎式结构：

```text
带全局 jitter 的低分辨率 Path Trace ─→ RR guides/noisy HDR ─→ DLSS RR
                                                              │
无 jitter 的输出分辨率 Primary Visibility ─→ stable ID/normal/depth/motion
                                                              │
                                                              ▼
                                       仅几何边界 Temporal Resolve
                                                              │
                           稳定 primary emissive ─────────────┤
                                                              ▼
                                                           ToneMap
```

关键决策：

- 不停止或缩小 Streamline 的全局 projection jitter；RR 输入契约保持不变。
- 不把新的稳定可见性纹理提交给 RR。它只供引擎自己的 RR 输出边界解析使用。
- 不增加完整光栅化管线。现有 TLAS 已经可用，用一次不求光照的 inline `RayQuery` 获取
  输出分辨率主可见性，是当前项目最直接的正确实现。
- 不做全屏 RR 输出累积。非边界像素必须逐值复制当前 RR 输出；只在 1–2 像素宽的真实
  几何边界附近重投影历史。
- 不在本轮接入 ReSTIR DI/GI、Frame Generation、透明层重构或新的曝光/锐化参数。

这不是用后处理掩盖错误。低分辨率 jitter 采样负责 RR 的时域超分辨率；独立无 jitter
主可见性负责判断输出像素属于哪个真实表面。两个职责分开后，墙角像素不会再因为低分辨率
采样位置改变而在两个材质之间交换历史。

## 2. 已确认的问题与基线

### 2.1 根因

当前 RR Quality 在 1280×720 输出时使用约 853×480 输入。`stage3_triangle.hlsl` 的主射线
位置包含每帧全局 `CameraJitterPx`。静止相机下 motion 是 0，但接缝附近少数低分辨率像素
仍会因为 jitter 改变而命中不同墙面：

- 121→122 帧 motion：0 个变化像素；
- normal/material ID：全图 796 个变化像素；
- 左接缝 normal/ID：6 个变化像素；
- 右接缝 normal/ID：9 个变化像素；
- 深度没有空洞，Cornell 墙面坐标也精确相接。

因此问题不是 geometry crack、错误 motion 或相机仍在移动，而是低分辨率 primary coverage
与硬材质/法线边界共同形成的 RR 时域输入不稳定。

### 2.2 当前最终图像参考

同一静止视角 121→122 帧、8-bit 最终输出的已记录参考：

| 区域 | RR Quality 平均最大通道差 | 差值 > 2 的像素 | 最大差值 |
|---|---:|---:|---:|
| 左侧绿/灰接缝 | 0.2717 | 0 | 2 |
| 右侧红/灰接缝 | 0.6453 | 723 | 7 |
| 后墙内部 | 0.2432 | — | — |

右侧更明显是因为红墙与灰墙的色度/亮度差更大，不代表右侧几何有额外裂缝。

### 2.3 为什么不能继续复用灯层修复

`stage11_rr_emissive.hlsl` 解决的是可直接识别的二值 primary emissive coverage；灯光层可从
noisy HDR 中严格拆出并在 RR 后加回。不透明墙面接缝属于 RR 已重建的随机反射光照，不能
再按材质把某一整层从 RR 输入中删除。它需要 surface-aware history validation，而不是第二个
“灯层冻结”。

## 3. 范围与不可破坏项

### 3.1 本轮必须实现

1. RR-only、输出分辨率、无 jitter 的主可见性 pass。
2. 稳定 surface ID、几何法线、当前/上一相机 viewZ 和输出像素 motion。
3. RR evaluate 后的边界 mask 与同表面时域解析。
4. reset、resize、generation、动画和 frame-context 资源生命周期。
5. 现有 debug view 的 RR 语义复用、GPU profiler 和有界 capture 证据。

### 3.2 本轮禁止实现

- 不把 `CameraJitterPx` 改成 0，不冻结 jitter phase，不改 Halton 序列。
- 不修改 RR 的 noisy HDR、albedo、normal/roughness、depth、motion、specular motion tags。
- 不进行全屏 EMA、全屏 history freeze 或普通 Gaussian/bilateral blur。
- 不跨 surface ID 采样历史，不允许先双线性历史颜色再检查中心 ID。
- 不用 ToneMap、曝光、Bloom 或 sharpen 参数把抖动隐藏起来。
- 不改 NRD、SVGF、DLSS SR 和 feature-off 默认路径的资源与执行顺序。
- 不引入 ReSTIR、Frame Generation 或新的第三方依赖。
- 不运行 600/1800 秒测试；单项自动测试最长 60 秒，首轮实机只做 1 秒 smoke 和定点 capture。

## 4. 资源与信号契约

资源只在 `streamline-rr` feature 且当前 generation `with_dlss_rr=true` 时创建。建议扩展
`RrGenerationResources`：

| 资源 | 格式/数量 | extent | 语义 |
|---|---|---|---|
| `primary_surface_id[2]` | `R32_UINT` × 2 | output | 当前/上一帧稳定 surface ID；miss=`0xFFFFFFFF` |
| `primary_surface_meta[2]` | `RGBA16_FLOAT` × 2 | output | `RG`=oct-encoded 当前几何法线，`B`=current viewZ，`A`=同一当前命中点的 previous-camera viewZ |
| `primary_motion` | `RG16_FLOAT` | output | `previousPixel-currentPixel`，单位为 output pixels；reset/miss 为 0 |
| `boundary_history[2]` | `RGBA16_FLOAT` × 2 | output | RGB=解析后的 RR HDR；A=有界 history count |
| `boundary_mask` | `R32_UINT` | output | bit flag，供调试与验收，不参与颜色计算 |

说明：

- ping/pong 索引继续使用现有 `current_history`/`previous_history`，不能再造第三套帧相位。
- `primary_surface_meta.B/A` 使用正的线性 viewZ。比较历史时，用当前像素保存的
  previous-camera viewZ 对比重投影位置的上一帧 current viewZ；不能直接比较两个相机空间
  下不相干的深度。
- 法线只用于表面连续性检查，采用插值后的**几何/顶点法线**，不采样 normal map。材质/primitive
  边界由稳定 ID 负责；省去纹理与 sampler 可保持 pass 便宜、确定且不改变 RR shading guide。
- `boundary_history` 使用 RR 输出的线性、pre-exposed HDR；ToneMap 之后的 LDR 不能进入历史。
- alpha 只保存 count，不承载颜色、surface ID 或透明度语义。

以 1920×1080 计算，本方案会增加约 95 MiB generation-owned 显存。必须在 JSON/现有显存
遥测中如实体现；不得为了省资源把 history 与 in-flight generation 共用或覆盖。

## 5. Stable Primary Visibility pass

新增 `shaders/stage11_rr_primary_visibility.hlsl`，编译为 `cs_6_6`。使用 inline
`RayQuery<RAY_FLAG_CULL_BACK_FACING_TRIANGLES | RAY_FLAG_FORCE_OPAQUE>`，因为当前 glTF loader
明确只接受 `OPAQUE` alpha mode，且应与现有 primary TraceRay 的背面规则保持一致。

### 5.1 输入

描述符表保持紧凑：

```text
t0 RaytracingAccelerationStructure TLAS
t1 StructuredBuffer<Vertex>
t2 StructuredBuffer<uint> indices
t3 StructuredBuffer<InstanceGpu>（当前 frame context）
u0 current primary_surface_id
u1 current primary_surface_meta
u2 primary_motion
b0 复用现有 16-DWORD CameraConstants
```

不要给通用 `ComputePipeline` 新增任意 bindless/root-SRV 抽象。本项目已有三个 frame-local
`InstanceGpu` upload buffer；给它们分别创建固定 SRV，并预建
`FRAME_CONTEXT_COUNT × 2 history phases` 描述符表。这样 descriptor 不会在 GPU 使用期间被
CPU 覆盖。需要在 `AccelerationStructures` 暴露只读的 frame-local instance resource/count
访问器；不得暴露可写映射指针。

### 5.2 射线和命中

- dispatch 为 output extent，线程组 `8×8`，边界线程必须先返回。
- 主射线固定从 `pixel + 0.5` 构造，明确不读取 `FrameIndex`、`CameraJitterPx` 或随机数。
- 相机 FOV/basis/投影必须与 `stage3_triangle.hlsl` 共用一个小型 `.hlsli`，或提取为一个明确
  的共享函数契约；禁止复制后靠肉眼保持两个常数 `2.747477419` 一致。
- 命中后通过 committed instance/primitive/barycentrics 计算 local position 和插值顶点法线；
  ID 使用 `InstanceGpu.stableSurfaceId`，不能直接把临时 `CommittedInstanceID()` 当稳定 ID。
- current world position 使用 committed object-to-world；previous world position 使用
  `InstanceGpu.previousObjectToWorld*`。
- current/previous UV 都由无 jitter 相机投影；motion 为
  `(previousUv-currentUv)*outputExtent`。静态场景必须逐像素为精确 0。
- 当前几何法线经过合法 front-face 定向、归一化、有限值检查，再 oct encode。
- miss 写 invalid ID、零 motion、约定的有限 meta；不得留下上一帧 UAV 内容。

### 5.3 调度位置

在 TLAS build/update 完成后、RR evaluate 前执行。它不依赖 Path Trace radiance，可以紧邻
Path Trace 后执行以复用已经绑定的 scene resources，但必须拥有独立 profiler pass 和明确
barrier：

```text
TLAS update → Path Trace → RR Primary Visibility → RR Input/Emissive Prep
            → RR Evaluate → RR Boundary Resolve → ToneMap
```

命名建议：`GpuPass::RrPrimaryVisibility`。

## 6. RR Boundary Resolve pass

新增 `shaders/stage11_rr_boundary_resolve.hlsl`，`cs_6_6`。输入/输出：

```text
t0 current RR output HDR
t1 current surface ID
t2 current surface meta
t3 current output-pixel motion
t4 previous surface ID
t5 previous surface meta
t6 previous boundary history
u0 current boundary history
u1 boundary mask
b0 ResetHistory
```

### 6.1 边界分类

中心像素检查 3×3 邻域。满足任意条件则为边界：

- 邻居 surface ID 与中心不同；
- ID 相同但解码法线点积低于 `0.95`；
- valid surface 与 miss 相邻。

不要用相邻像素的绝对 viewZ 差单独检测边界；斜平面天然存在深度梯度，会把整面墙误判为
边界。ID 与法线足以覆盖当前材质接缝、轮廓和同一 primitive 内的硬法线边。

非边界像素必须：

```hlsl
CurrentHistory[p] = float4(CurrentRr[p].rgb, 1.0);
BoundaryMask[p] = 0;
```

即最终颜色与 RR 当前输出逐值一致，不允许额外滤波。

### 6.2 历史重投影与验证

边界像素使用 `previousPosition = pixel + primary_motion`。历史采用手写 2×2 gather，逐 tap
验证后再归一化权重。每个 tap 必须同时满足：

1. previous ID 等于 current ID，且双方都不是 invalid；
2. previous normal 与 current normal 的点积至少 `0.95`；
3. previous meta 的 current viewZ，与 current meta 保存的 previous-camera viewZ 相对误差
   不超过 `1%`，绝对最小容差 `0.01`；
4. history RGB/count 有限且 count > 0。

有效双线性权重和小于 `0.25` 时拒绝历史。严格禁止先对颜色、ID 或 normal 做普通双线性，
再用中心样本决定接受；那会把红墙历史混入灰墙。

### 6.3 同表面 clamp 与累积

- 从 current RR output 的 3×3 邻域中只收集与中心 current ID 相同的像素。
- 将 RGB 转成 YCoCg，计算同表面 current min/max，并用小的相对扩张后 clamp 历史，再转回
  RGB。不要用跨 ID 的颜色范围。
- 若 clamp 后历史与 current 的亮度差超过有名称的 HDR shading-rejection 阈值，拒绝或把
  history count 降到 1；阈值必须写成常量并注释其单位/目的，不能散落 magic number。
- 静态有效历史最多累积 32 帧：`weight=count/(count+1)`，然后把 count 截断到 32。
- motion 大于 0.5 output pixel 时把最大有效 count 限制为 4；大于 2 pixels 时拒绝历史。
- 不使用“count 到 32 后直接复制上一帧”的永久 freeze。bounded accumulation 配合深度、
  法线、ID 和 shading rejection，既稳定静态接缝，也能响应灯光/动画变化。
- `ResetHistory != 0`、越界、NaN/Inf、miss 或验证失败时直接采用 current RR。

建议 mask bit：

| bit | 含义 |
|---:|---|
| 0 | 当前像素处于稳定 primary surface 边界 |
| 1 | 没有足够的同 ID 历史 tap |
| 2 | normal/depth 验证拒绝 |
| 3 | HDR shading rejection |
| 4 | reset/out-of-bounds/invalid |

命名建议：`GpuPass::RrBoundaryResolve`。

## 7. 合成、debug 与生命周期

### 7.1 合成顺序

RR active 时 ToneMap 的 `t0` 从 `rr.output_hdr` 改为当前 `boundary_history`。现有稳定
primary-emissive history 仍绑定 `t1` 并只加一次：

```text
ToneMap(boundary_resolved_rr_hdr + stable_primary_emissive)
```

不得把 primary emissive 写进 boundary history，否则灯层会被重复累计或无法独立 reset。

### 7.2 复用现有 debug view

避免再扩展 F1 枚举，本轮在 RR ToneMap descriptor table 中复用：

- `object-material-id`：`t11` 绑定当前 output-resolution stable surface ID；
- `history-rejection`：`t9` 绑定 boundary mask；
- `motion`：`t7` 绑定 output-resolution primary motion；
- `final`：显示 boundary resolved RR + stable primary emissive。

非 RR 路径保持现有绑定和标题。RR debug 输入必须都是 output extent，避免 ToneMap 因以
`t0` 判断 native size 而对低分辨率 guide 越界读取。本轮若发现 RR 其它旧 debug view 仍混用
render/output extent，只允许做保证安全的 descriptor/采样修复，不扩展成 debug 系统重写。

### 7.3 reset 与 generation

沿用现有 `reset_history`，以下事件必须让 boundary history 从当前帧重新开始：

- 相机 teleport/不连续切换；
- RR quality、render extent、output extent 或 reconstruction backend 改变；
- resize、shader hot reload、generation 创建/切换；
- 模型加载或实例拓扑/stable ID 重新分配。

正常相机移动和连续实例动画不全局 reset，依靠 output motion 重投影。资源退休继续由
generation fence 管理；不得增加正常帧 `wait_for_gpu`。

## 10. Codex review 清单

Luna 完成后，Codex 按提交顺序 review，重点检查：

1. stable visibility 是否真的使用 output pixel center 且完全不读 jitter/随机数；
2. ID 是否来自 `stableSurfaceId`，frame-local instance descriptor 是否存在 in-flight 覆盖；
3. current/previous viewZ 是否处于正确相机空间，motion 方向/单位是否为 previous-current/output px；
4. 历史是否逐 tap 验证后才插值，是否存在跨 ID bilinear 泄漏；
5. 非边界是否精确 passthrough，mask 是否被无意膨胀到整面墙；
6. clamp 是否只读取同 ID current 邻域，是否在 pre-exposed HDR 中工作；
7. reset、generation retirement、resize 和 hot reload 是否无正常帧 GPU idle；
8. RR tags、灯层、NRD/SVGF/DLSS SR 和 feature-off 资源是否保持不变；
9. profiler/JSON/capture 是否证明真实 pass 执行，而不是只靠 `shader.contains()` 测试；
10. 注释是否解释 jitter 分工、跨表面历史风险和 viewZ 比较原因，而不是逐行复述代码。

出现以下任一情况，review 直接判为必须修复：

- 静止画面靠停 jitter 或全屏 freeze 才稳定；
- 边界历史先双线性混色后才检查 ID；
- normal/depth/ID 任一无效时仍使用历史；
- 非边界像素经过额外 temporal filter；
- capture 指标改善但出现相机移动拖尾；
- 为通过测试修改 ROI、曝光、ToneMap 或验收阈值。

## 11. 完成定义与后续

本计划完成表示：RR 静止不透明墙角接缝达到稳定、运动时无明显跨表面鬼影，且默认/NRD/
SVGF/DLSS SR 路径没有回退。它不表示阶段 11 全部完成；Frame Generation 仍按原计划独立推进。

完成后再决定是否接入 ReSTIR DI。ReSTIR DI 解决的是进入 RR 前的直接光采样方差，对整面墙、
阴影和高光的噪声有价值，但不能替代本计划的 primary surface 边界归属与历史拒绝。
