# 阶段 11F-R：RR 有界收口验收记录

日期：2026-08-13
目标 GPU：NVIDIA GeForce RTX 4060 Laptop GPU
固定 Streamline：v2.12.0
范围：RR 有界验收 runner、Debug descriptor 修复和证据可信性收口；没有实现 11G、Frame Generation、swap chain/proxy device/factory 改造。

## 1. 实现范围

新增 `scripts/stage11_rr_acceptance.ps1`，不复制 Stage 10 runner 的渲染流程：

- Native、DLSS SR、NRD 基线通过 `scripts/stage10_acceptance.ps1 -CaseName ...` 单 case 运行，读取其 `summary.json`；
- 本脚本只调度 RR Quality/Balanced/Performance、Triangle 动画和 RR Debug；
- 每个实际 D3D/GUI 子进程都保存 args、stdout、stderr、exit JSON，并使用 `Start-Process`、有界 `WaitForExit` 和 PID 树终止；
- benchmark stdout 必须恰好为一行且该行必须是 JSON；Streamline 签名诊断在 SDK 生命周期内重定向到 stderr 并原样保留；
- gate 覆盖 RR profile、active RR pass、SVGF/NRD/普通 SR 隐藏成本、GPU idle wait、optimal extent、显存比例、Reflex/PCL 对账、错误输出和 Debug InfoQueue；
- runner 拒绝 staged/unstaged/untracked dirty tree，并核对 EXE 内嵌的 commit、tree、dirty 和 Cargo features；锁文件外的 DLL hash、错误 production/development flavor 也会失败；
- runner 验证 `a09748f` 位于当前 HEAD 祖先链，并确认 `image_diff --roi` 的 metric/parser 单测仍存在；
- `-SelfTest` 不启动 GPU，包含一个合法正例和 11 个拒绝用例。

没有修改 shader、ToneMap、曝光、采样、ROI 或既有阈值。为消除 Debug Layer 错误，RR primary visibility 的 TLAS/vertex/index SRV 改为直接创建，不再从 shader-visible heap 非法复制 descriptor。

## 3. 自动检查和隔离构建

以下命令均退出码 0；`cargo test --all-features --locked` 为 image_diff 6 项和主程序 154 项通过，`SelfTest` 为一个合法正例和 11 个拒绝用例通过：

```text
cargo fmt --all -- --check
cargo test --all-features --locked
cargo clippy --all-features --all-targets --locked -- -D warnings
git diff --check
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/stage11_rr_acceptance.ps1 -SelfTest
```

使用独立 target 目录构建，runner 没有 Cargo build，也没有复制 EXE/DLL：

```powershell
$env:CARGO_TARGET_DIR='target/stage11rr-default'; cargo build --release --locked
$env:CARGO_TARGET_DIR='target/stage11rr-rr'; cargo build --release --features streamline-rr --locked
$env:CARGO_TARGET_DIR='target/stage11rr-nrd-streamline'; cargo build --release --features nrd,streamline --locked
$env:CARGO_TARGET_DIR='target/stage11rr-rr-debug'; cargo build --features streamline-rr --locked
```

四个构建成功。Streamline Release 构建有仓库已有的 dead-code warning；没有用全局 allow 掩盖。正式 Matrix 的 git/tree、EXE hash、SDK/DLL hash 和环境来源都绑定在 runner summary 内。
