## 1. 任务定位

- 方案日期：2026-08-09。
- 目标硬件：NVIDIA GeForce RTX 4060 Laptop GPU。
- 执行基线：`ba76cb4`，其中 `40acb1b` 是本轮必须验证的代码/runner 修复。
- 执行者：Luna；完成后由 Codex review。
- 当前状态：**Luna 已在 `bf0aba3` 回填短矩阵；Codex review 接受 20 个 30 秒 raw run、54/23 capture/diff 和动态代际证据，但发现 median 计算、Debug raw 留存和环境快照缺陷。下一包见 [`阶段8G短矩阵Review修复与1080p性能归因执行方案.md`](阶段8G短矩阵Review修复与1080p性能归因执行方案.md)。**
- 本包性质：验收执行和证据回填，不是新的渲染功能开发。

本包只关闭当前机器上能够在合理时间内自动复验的项目：Release 30 秒短矩阵、确定性 capture/diff、短 Debug GPU Validation 和结果文档。30 分钟显存/动态生命周期、真实键盘交互、公开 PBR/大模型和 PIX UI 继续保留为独立债务，不得冒充通过。

本包不得修改 Path Trace、随机采样、Temporal、À-Trous、ToneMap、动态分辨率控制公式或默认模式。若复验失败，先保留原始证据并报告，不得通过放宽阈值、减少矩阵、挑选最好一次或修改算法来制造 PASS。

## 2. 已知基线与需要复核的问题

Codex review 已确认并修复：

1. capture pending 后继续提交后续帧，可能在 PNG 完成退出时仍有在飞帧引用 renderer 资源；`40acb1b` 已让 capture fence 成为退出前最后一个 submitted fence。
2. 旧 runner 只凭 `image_diff` exit code 判断通过，没有强制像素阈值；修复后 exact 和 À-Trous tolerance 都在 summary 中硬校验。
3. 旧 default dynamic 实际 output 为 1280×720，不满足 1920×1080 output 验收。
4. 旧 1800 秒 forced-dynamic 运行在 1280×720 下 `switch_count=0`，只能作为显存稳定诊断，不能作为动态 generation 生命周期证据。
5. 旧 AS capture 没有加载 glTF，实际是 Cornell；修复后的 AS 矩阵显式使用 `assets/gltf/Triangle/NonIndexedMultiNode.gltf`。
6. 旧 1080p fixed 三次 p95 中位数为 8.00 ms，相对 8E-2 的最差参考 7.44 ms 回退约 7.5%，超过 3% 门槛 7.6632 ms，必须由同一 runner 的受控短矩阵诚实复核。

已通过的 3 秒 smoke 目录为 `output/stage8g/20260809-183211-9b0810ff/`。它证明修复后的 runner 能发现 measurement 内真实切换并完成 generation/history/VRAM 对账，但不能代替本方案的正式 30 秒矩阵。

## 6. 工作包 R2：Release 完整短矩阵

### 6.1 唯一正式命令

从仓库根目录运行：

```powershell
.\scripts\stage8_acceptance.ps1 `
  -Configuration Release `
  -Runs 3 `
  -Seconds 30 `
  -SkipLongRun
```

必须为外层执行工具提供不少于 20 分钟、建议 30 分钟的命令超时；这只是允许 30 秒 case 和 capture 矩阵正常收尾，不是允许任何长测。**不得传 `-LargeModel` 或 `-PbrModel`，不得去掉 `-SkipLongRun`。**

预计 runner 自动执行：

- 1 次 1920×1080、target 4 ms forced-dynamic smoke；
- fixed 1280×720、1600×900、1920×1080，各 3×30 秒；
- 1920×1080 output 下 scale 0.83/0.75/0.67，各 1×30 秒；
- 1920×1080 default dynamic，3×30 秒；
- `NonIndexedMultiNode.gltf` static/animated × AS baseline/optimized，各 1×30 秒；
- 54 张 1280×720、128 SPP capture；
- 11 组 command exact diff、11 组 glTF AS exact diff、1 组 À-Trous tolerance diff。

### 6.2 runner 退出规则

- smoke 失败：runner 应停止；保留该 run-id，停止本包并报告。
- 后续 case 失败：允许 runner 完成剩余矩阵并写 summary，但最终 exit code 应为非零。
- runner 非零不等于脚本崩溃。先读取最新 `output/stage8g/<run-id>/summary.json`，区分验收门槛失败、capture/diff 失败、进程异常和汇总异常。
- 不得自动重跑失败 case，不得用第二次运行替换第一次。若环境明显被外部 resize/断电污染，保留第一次证据并请求用户决定是否完整重跑。

### 6.3 必须核对的 summary 契约

逐项核对并写入报告：

1. `summary.passed`、每个 case 的 `passed/failures` 和最终进程 exit code一致。
2. 每次 benchmark stdout 只有一行 JSON，`valid_samples > 0`，所有 pass 的 p95 有限且不小于 p50，pass 样本数与 Total 一致。
3. fixed case 的 generation create/switch/retired、extent change、history reset 和 idle wait 均为 0。
4. dynamic 的 Total samples 等于 controller valid + stale；switch 等于 down + up；generation create/switch/retired、extent/history 与 measurement switch 对账；最终 retired 为 0、high-watermark不超过 2、idle wait 为 0。
5. 所有 output/render extent 与 case 期望一致；固定 1920×1080 scale 0.83/0.75/0.67 分别是 1592×896、1440×808、1280×720。
6. 每次显存 measurement 有有效 query、结束时 inactive、checkpoint 数组与 count 一致，peak ratio 小于 70%。
7. 1080p fixed 和 default dynamic 的 Total p95 都不超过 16.67 ms；1080p fixed 三次 p95 中位数还必须不超过 7.6632 ms。
8. forced smoke 在 measurement 内至少发生一次真实动态切换。
9. capture 记录共 54 项，全部实际 SPP 至少 128、view/output/path/PNG bytes 正确并有 SHA-256。
10. diff 记录共 23 项：22 个 exact 对 changed/alpha/max/RMSE 全零；À-Trous 对 alpha 为零、max abs 不超过 1、RMSE 不超过 0.10。

## 7. 工作包 R3：短 Debug GPU Validation

Release runner 完成后，使用 Debug executable 执行下列短命令。每条 benchmark 只有 1 秒；不要扩展时长：

```powershell
.\target\debug\ray_tracing_demo.exe --benchmark-seconds 1 --output-size 320x180 --command-recording-mode baseline --atrous-mode baseline --acceleration-structure-mode baseline
.\target\debug\ray_tracing_demo.exe --benchmark-seconds 1 --output-size 320x180 --dynamic-resolution --target-gpu-ms 4 --command-recording-mode optimized --atrous-mode baseline --acceleration-structure-mode baseline
.\target\debug\ray_tracing_demo.exe --model assets\gltf\Triangle\NonIndexedMultiNode.gltf --benchmark-seconds 1 --output-size 320x180 --acceleration-structure-mode optimized
.\target\debug\ray_tracing_demo.exe --model assets\gltf\Triangle\NonIndexedMultiNode.gltf --animate-model --benchmark-seconds 1 --output-size 320x180 --acceleration-structure-mode optimized
```

另做一条 Debug readback：

```powershell
.\target\debug\ray_tracing_demo.exe `
  --model assets\gltf\Triangle\NonIndexedMultiNode.gltf `
  --acceleration-structure-mode optimized `
  --capture-output output\stage8g\<run-id>\debug-gltf-as-capture.png `
  --capture-after-spp 8 `
  --output-size 320x180 `
  --debug-view object-material-id
```

每条记录命令、退出码和 stderr 末尾 InfoQueue 结论。要求无 Device Removed、panic、resource state、AS lifetime、readback footprint、descriptor 或 fence 错误；Debug 正常退出应报告 `D3D12 Debug InfoQueue：0 条消息`。

本包不自动发送 F1/F2，不做 resize/minimize/hot-reload 的 GUI 焦点脚本。若 Luna 没有可信的窗口观察能力，相关项保持 `PENDING MANUAL`，不得写 PASS。
