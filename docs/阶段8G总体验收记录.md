## 2. 实现摘要

- `DebugView` 使用固定 11 项枚举，CLI、F1 顺序、ToneMap root constant、capture metadata 共用同一映射；resize、F2 和动态控制阻断使用稳定 stderr 诊断行。
- capture 只从 `display_output` 记录 `CopyTextureRegion`，位置在 Total timestamp/PIX event 结束之后、swap-chain copy 之前；readback 由 pending fence 持有，只有 fence 完成后 Map，按 D3D12 footprint row pitch 去除 padding，再原子写 PNG。
- `image_diff` 是独立 binary，Cargo `default-run` 仍为 `ray_tracing_demo`；不兼容尺寸返回非零，成功 stdout 是一行 JSON。
- `VideoMemoryTelemetry` 继续查询实际选中的 adapter 的 `IDXGIAdapter3` local segment，约 500 ms 查询一次；benchmark measurement 固定 60 个 60 秒 checkpoint，统计 start/end/peak usage、minimum budget、peak ratio、valid/failed query。
- capture 进入 pending 后不再提交更晚的帧，确保 capture fence 是退出前最后一个 submitted fence，避免写完 PNG 后销毁仍被后续在飞帧引用的 renderer 资源。
- runner 现在按每个 case 校验 output/render extent、模式、p50/p95、样本数、动态 epoch、generation 创建/切换/回收、history reset、idle wait、显存峰值和性能门槛；image diff 必须满足像素阈值，而不再只检查 exit code。
- 正式矩阵改为 1920×1080 output：固定 scale 校验量化后的 render extent，forced dynamic 必须在 measurement 内发生切换；AS 截图使用仓库 glTF fixture，11 个 DebugView 均执行 command/AS baseline-vs-optimized diff。
- 8F 未实现；没有修改 Path Trace、随机采样、Temporal、À-Trous、ToneMap 或动态分辨率控制公式。

## 5. 强制动态 smoke 和 1800 秒长测

旧实现先运行了强制动态 `--dynamic-resolution --target-gpu-ms 4` 的 30 秒 smoke；raw JSON 通过当时有限的 valid sample、dynamic epoch 和有限数值检查。旧长测命令为：

```text
target\release\ray_tracing_demo.exe --benchmark-seconds 1800 --command-recording-mode optimized --atrous-mode baseline --acceleration-structure-mode baseline --output-size 1280x720 --dynamic-resolution --target-gpu-ms 4
```

旧长测结果：

- 运行约 1800 秒，`valid_samples=431567`，动态 measurement `valid_samples=431567`，`stale_generation_samples_ignored=0`，`switch_count=0`。
- output/render 始终为 1280×720，generation create/switch/retire 均为 0（初始 generation 不计入 measurement），`gpu_idle_wait_count=0`，history reset 为 0。
- Total `3.16/3.48`，AS `0/0`，Path Trace `1.42/1.85`，Temporal `0.41/0.86`，À-Trous 聚合 `0.91/1.51`，四轮分别 `0.24/0.64`、`0.22/0.59`、`0.22/0.24`、`0.23/0.59`，ToneMap `0.04/0.06` ms。
- 显存 measurement 有 31 个 checkpoint（0、60、…、1800 秒），valid query 3584、failed query 0；start usage 326,074,368 B，end/peak usage 327,131,136 B，minimum budget 7,537,164,288 B，peak ratio 4.3402%。

由于 Total p95 `3.48 ms` 低于 forced target 的 high threshold `5 ms`，measurement 内 `switch_count=0`。因此这份数据可以证明 720p 固定工作负载下 30 分钟显存没有持续增长、idle wait 为 0，但没有覆盖动态 generation 生命周期，不能称为 forced-dynamic 长测通过。修复后的 runner 使用 1920×1080 output，并要求 measurement 内至少一次真实动态切换。本轮按用户要求未重跑该长测。

## 6. Deterministic capture 和 image diff

旧 Release capture 矩阵共生成 53 张 PNG，全部位于 `output/stage8g/20260809-172437-113b460b/captures-matrix/`，每张为 1280×720、实际 128 SPP、RTX 4060 Laptop GPU。覆盖：

- command-recording baseline/optimized × 11 DebugView；
- acceleration-structure baseline/optimized × 11 DebugView；
- À-Trous baseline/shared final；
- fixed scale 0.83/0.75/0.67 final；
- dynamic default/forced 的 final 和 history-length。

后处理执行了 23 个 image diff（11 个 command 对、11 个 AS 对、1 个 À-Trous 对），现有 JSON 全部为零。原始 diff JSON 在 `output/stage8g/20260809-172437-113b460b/diffs-matrix/`。但是旧 runner 源码只对最后一个 command view 执行 diff，且 `image_diff` 即使像素不同也会 exit 0；旧 runner 因而不能自动重现或强制这 23 个阈值。修复后 exact 对要求 changed/alpha/max/RMSE 全零，À-Trous 对要求 alpha 为零、max abs 不超过 1、RMSE 不超过 0.10。

此外，旧 AS capture 命令没有传 `--model`，实际仍是 Cornell，并未覆盖 glTF AS baseline/optimized。修复后的矩阵显式加载 `assets/gltf/Triangle/NonIndexedMultiNode.gltf`，但本轮未执行完整 128 SPP 矩阵，因此 glTF AS capture/diff 仍待重跑。

这证明了 capture 源、PNG row-pitch 解包和这些 CLI 参数组合之间的确定性；它不证明用户实际按键 F1/F2，也不替代人工画面观察。
