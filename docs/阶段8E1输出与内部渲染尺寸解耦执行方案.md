## 3. 当前代码事实与风险

当前 `Dx12Renderer` 只有 `width`/`height`，它们同时驱动以下内容：

- swapchain 和 `display_output`；
- 9 个 DXR 帧输入 UAV；
- 两套 Temporal history；
- À-Trous ping/pong 和 rejection mask；
- `DispatchRays`、Temporal、À-Trous、ToneMap 的 dispatch 尺寸；
- 单一的 320 项 shader-visible heap。

`resize()` 会 `wait_for_gpu()`，释放所有尺寸相关资源、`ResizeBuffers`，然后在原 heap 的相同槽位重写 descriptor。这个流程适合真正的 swapchain resize，但不能用于每次内部尺寸变化：GPU 可能仍在读取旧 heap 中的 descriptor，原地覆盖会造成 descriptor 生命周期错误；每次全局等待又会让 8E-2 无法工作。

另一个关键事实是 ToneMap 目前按内部纹理的像素坐标直接 `Load`，并按同一尺寸 dispatch。只改变 DXR dispatch 而不改变 ToneMap，会导致输出未写满或越界读取。

## 4. 尺寸模型

### 4.1 建议的纯 Rust 类型

在 Windows/D3D12 代码之外新增可单元测试模块，例如 `src/resolution.rs`：

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Extent2D {
    pub width: u32,
    pub height: u32,
}

#[derive(Clone, Copy, Debug, PartialEq)]
pub struct RenderScale(f32);

impl RenderScale {
    pub const NATIVE: Self = Self(1.0);
    pub fn new(value: f32) -> Result<Self, RenderScaleError>;
    pub fn get(self) -> f32;
}

pub fn render_extent(output: Extent2D, scale: RenderScale) -> Extent2D;
```

`RenderScale::new` 必须拒绝：

- `NaN`、`+inf`、`-inf`；
- 小于 `0.5`；
- 大于 `1.0`。

不要在渲染循环里散落裸 `f32` 范围判断。`RenderScale` 内部字段保持私有，使“有限且在范围内”成为类型不变量。若为它实现 `Eq`，必须基于该不变量或 `to_bits()`，不能让 NaN 进入类型。

### 4.2 唯一量化规则

```text
scale == 1.0:
    render_extent = output_extent（逐维精确相等）

scale < 1.0:
    render_width  = clamp(floor(output_width  * scale / 8) * 8, 8, output_width)
    render_height = clamp(floor(output_height * scale / 8) * 8, 8, output_height)
```

使用 `f64` 或经过检查的整数运算计算中间值，最后再转 `u32`，避免溢出和不稳定舍入。只有量化后的 extent 变化才创建新代。

这里刻意给 `1.0` 原生路径例外：1920×1080 的高度不是 8 的倍数；若强行对齐会破坏“默认行为和原生输出一致”。所有 dispatch 仍须使用 `div_ceil(8)` 并在 shader 中保留边界检查。

应固定以下单元测试期望：

| output | requested scale | render extent |
| --- | ---: | --- |
| 1920×1080 | 1.00 | 1920×1080 |
| 1920×1080 | 0.83 | 1592×896 |
| 1920×1080 | 0.75 | 1440×808 |
| 1920×1080 | 0.67 | 1280×720 |
| 1280×720 | 0.67 | 856×480 |
| 321×181 | 1.00 | 321×181 |

还要覆盖单调性、永不为 0、降采样不超过输出、相同量化结果不触发切换。

## 5. 资源归属

### 5.1 输出尺寸资源

| 资源 | 尺寸 | 所有者 |
| --- | --- | --- |
| 3 个 swapchain back buffer | `output_extent` | `Dx12Renderer` |
| RTV heap | 与 back buffer 数量相关 | `Dx12Renderer` |
| `display_output` | `output_extent` | 当前 render generation |

### 5.2 内部尺寸资源

以下资源全部使用 `render_extent`，并归属于当前 generation：

- `raw_diffuse`、`raw_specular`；
- `gbuffer_albedo`、`gbuffer_normal_roughness`、`gbuffer_depth`、`gbuffer_motion`、`gbuffer_id`、`gbuffer_world_position`、`gbuffer_hit_distance`；
- 两套 `DenoiseHistory`；
- diffuse/specular ping/pong；
- `rejection_mask`。

场景 geometry、材质 buffer、纹理、sampler heap、BLAS/TLAS、pipeline、frame context、GPU profiler 不属于 render generation，不随内部尺寸重复创建。

### 5.3 建议的数据结构

优先把尺寸资源从已经很大的 `src/renderer/d3d12.rs` 拆到 `src/renderer/d3d12/render_resources.rs`：

```rust
struct FrameInputs {
    raw_diffuse: TrackedResource,
    raw_specular: TrackedResource,
    // 其余 GBuffer……
}

struct FilterResources {
    diffuse_ping: TrackedResource,
    diffuse_pong: TrackedResource,
    specular_ping: TrackedResource,
    specular_pong: TrackedResource,
    rejection_mask: TrackedResource,
}

struct RenderResourceGeneration {
    id: u64,
    output_extent: Extent2D,
    render_extent: Extent2D,
    shader_heap: DescriptorHeap,
    display_output: TrackedResource,
    frame_inputs: FrameInputs,
    histories: [DenoiseHistory; 2],
    filter: FilterResources,
    last_used_fence: u64,
}

struct RetiredRenderResourceGeneration {
    retire_fence: u64,
    resources: RenderResourceGeneration,
}
```

`Dx12Renderer` 改为拥有：

```rust
output_extent: Extent2D,
requested_render_scale: RenderScale,
active_generation: RenderResourceGeneration,
retired_generations: VecDeque<RetiredRenderResourceGeneration>,
next_generation_id: u64,
```

生产路径不再为每个尺寸资源保存 `Option<TrackedResource>`。初始化时先完整创建 generation，成功后再构造/替换 renderer；不要靠一串 `unwrap()` 表示“理论上已初始化”。

## 6. Descriptor heap 规则

每个 generation 必须创建完整的 320 项 shader-visible CBV/SRV/UAV heap，保持当前槽位布局不变。不能只为动态 UAV 创建小 heap，因为一次 draw/dispatch 只能绑定当前 heap，DXR 表中的 TLAS、geometry、材质和场景纹理也必须在同一个 heap 中可见。

创建新代时，按现有布局重新写入：

1. slot 0：当前 TLAS GPU VA；
2. slot 1–3：vertex/index/material structured SRV；
3. 场景纹理 SRV；
4. DXR 的 9 个 render-sized UAV；
5. 两套 Temporal、À-Trous、ToneMap 表。

静态 descriptor 指向的底层资源仍由 renderer 长期持有，重写 descriptor 不复制底层资源。sampler heap 继续全局稳定。

所有 pass 必须从同一个 `active_generation.shader_heap` 取得 GPU handle。禁止出现“绑定新 heap，却拿旧 heap 的 table handle”的混用。

保留并扩展现有 descriptor table 不重叠测试；新测试还应确认 generation heap 的静态/动态写入范围都不超过 320。

## 7. 创建、切换与退休

### 7.1 创建必须是事务性的

内部尺寸变化时先在局部变量中创建完整新代并写完 descriptor。只有全部成功后才能切换 `active_generation`。创建失败时：

- 旧代继续有效；
- generation id、切换计数和 history reset 计数不增加；
- 错误带创建阶段和目标 extent 上下文返回给调用方。

### 7.2 精确记录最后使用 fence

不要用 `next_fence_value - 1` 猜测旧代最后一次使用。每次 frame command list 提交并成功 `Signal` 后：

```text
active_generation.last_used_fence = frame_fence_value
```

F2 或未来 8E-2 只允许在帧边界调用切换函数。切换时：

1. 新代已经完整创建；
2. `mem::replace` 切为新代；
3. 若旧代 `last_used_fence == 0`，说明从未提交给 GPU，可立即释放；
4. 否则连同该 fence 放入 `retired_generations`；
5. `history_index = 0`，调用现有 `request_history_reset()`；
6. `accumulated_frames = 0`，previous camera 同步到 current camera；
7. 只在量化 extent 真正变化时增加 `render_extent_change_count`。

### 7.3 退休回收

每帧在取得 completed fence 后调用回收：

```text
while front.retire_fence <= fence.GetCompletedValue():
    pop_front and drop
```

如果队列不保证 fence 单调，就使用 `retain`；更推荐保证提交顺序并用 `VecDeque`。不得仅按 `FRAME_COUNT` 或 CPU 帧数猜测安全期。

内部 scale 切换路径中严禁：

- `wait_for_gpu()`；
- `WaitForSingleObject()`；
- `ResizeBuffers()`；
- 覆盖 active/retired generation 的 descriptor；
- 在 fence 完成前 drop 旧资源或 heap。

### 7.4 真正的 output resize

swapchain `ResizeBuffers()` 仍允许并必须使用全 GPU 等待。保持当前“等待、重置 command list 以释放 back buffer 引用、释放 back buffer、ResizeBuffers”的安全顺序。

等待完成后可以清空 retired generations；按新的 `output_extent` 和当前 requested scale 创建一代新资源。若窗口最小化为 0×0，只记录 minimized，不创建 0 尺寸资源。最小化期间按 F2 时只更新 requested scale/pending 状态，恢复时一次性创建最终所需 generation。

shader hot reload 和 shutdown 仍允许现有全 GPU 等待；不要为了本包把 pipeline 也代际化。

## 8. Render loop 的尺寸使用

每帧只读取一次 active generation 的两个 extent，避免过程中切换：

| 阶段 | dispatch/copy 尺寸 |
| --- | --- |
| `DispatchRays` | `render_extent.width × render_extent.height` |
| Temporal | `render_extent.div_ceil(8)` |
| À-Trous 四次 | `render_extent.div_ceil(8)` |
| ToneMap | `output_extent.div_ceil(8)` |
| `CopyResource(display_output -> back buffer)` | 两者都为 `output_extent`，格式不变 |

所有 DXR/Temporal/À-Trous shader 已按资源或 dispatch dimensions 做边界检查，不能删。相机 aspect 和 motion vector 必须继续基于 `DispatchRaysDimensions()`，也就是内部尺寸；不要误改为 output extent。

内部切换发生在窗口事件的帧边界，不能在 command list 已开始记录后替换 generation。

## 9. ToneMap 与 F1 采样

### 9.1 不改变 root layout

继续使用 `stage6_tonemap.hlsl` 现有 13 SRV、1 UAV、2 个 root constants。shader 可通过 `Output.GetDimensions()` 得到 output extent，通过任一内部 SRV（例如 `FilteredDiffuse.GetDimensions()`）得到 render extent，不需要增加 sampler 或 root constants。

为了保持 `--render-scale 1.0` 行为，两个 extent 完全相等时走原来的直接 `Load(pixel)` 路径。这也避免不必要的浮点映射差异。

### 9.2 连续量：手写双线性 Load

当前 ToneMap root signature 没有 sampler。本包使用 4 次 `Texture2D.Load` 和 `lerp`，不要扩大 root signature：

```text
source_position = (output_pixel + 0.5) * render_extent / output_extent - 0.5
base = floor(source_position)
fraction = frac(source_position)
p00/p10/p01/p11 = clamp(base + offsets, 0, render_extent - 1)
value = bilinear(load(p00), load(p10), load(p01), load(p11), fraction)
```

注意先计算 fraction，再 clamp 各采样坐标；否则边缘权重会错误。按实际 HLSL 类型提供 `float4`、`float2`、`float` helper，避免隐式类型转换。

### 9.3 离散量：像素中心 point Load

使用像素中心映射到唯一源 texel，再 clamp：

```text
source = min(((2 * output_pixel + 1) * render_extent) / (2 * output_extent), render_extent - 1)
```

尺寸上限 7680，32 位 `uint` 乘法安全。离散值必须先 point load，再进行颜色编码；绝不能先把 ID/mask/history length 转颜色后双线性插值。

### 9.4 11 个视图的固定规则

| F1 mode | 视图 | 采样规则 |
| ---: | --- | --- |
| 0 | 最终 filtered diffuse/specular + albedo | 各连续信号双线性，再组合和 ToneMap |
| 1 | 原始 1 SPP | RawDiffuse/RawSpecular 双线性 |
| 2 | 反照率 | 双线性 |
| 3 | 法线/粗糙度 | 双线性，仅用于显示 |
| 4 | 深度 | 双线性后做现有可视化映射 |
| 5 | 运动矢量 | 双线性 |
| 6 | 方差/moments | moments 双线性后计算方差 |
| 7 | 历史拒绝原因 | `RejectionMask` point load 后着色 |
| 8 | 历史长度 | `HistoryLength` point load 后着色 |
| 9 | 物体/材质 ID | `Id` point load 后哈希着色 |
| 10 | 镜面命中距离 | 双线性后做现有映射 |

## 10. History 正确性

新 committed texture 的内容未定义。当前 Temporal shader 在 `ResetHistory != 0` 时不会读取 previous history，并且会对 dispatch 覆盖的每个内部像素写出 diffuse/specular/moments/normal/depth/length/id/world position/hit distance/rejection。À-Trous 随后只读取本帧写好的 current history。

因此本包不需要为了“看起来清零”而插入额外 GPU clear，但必须保持以下不变量并用注释说明：

- 新代第一帧 `reset_history == true`；
- current history 和 rejection mask 在任何读取前由完整 Temporal dispatch 写满；
- 第一帧 timing sample 继续标为无效；
- 如果未来改成 partial dispatch，必须先增加明确的 ClearUAV/初始化步骤。

## 15. Review 阻断项

出现以下任一项，不接受 8E-1：

- `--render-scale 1.0` 仍把 1080 向下对齐为 1072；
- 只换内部纹理却让 ToneMap 仍按 render extent dispatch；
- 对 ID、mask 或 history length 做双线性插值；
- 内部切换复用并覆盖旧 shader heap；
- F2 路径调用 `wait_for_gpu()` 或 `ResizeBuffers()`；
- 用固定 3 帧延迟代替 fence 判定资源生命周期；
- 新 generation 创建失败后 active 状态被部分替换；
- 新代首帧没有 history reset；
- JSON 仍把 render 尺寸写成 output 尺寸；
- 为完成 8E-1 顺手加入未经测试的 dynamic controller 或上采样算法；
- 文档把未做的截图/50 次切换/Debug 验证写成已通过。
