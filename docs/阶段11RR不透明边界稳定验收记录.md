# 阶段 11 RR 不透明边界稳定验收记录

## 1. 范围与环境

- 验收对象：`586a819`（边界足迹与静止历史）和 `3d9d462`（debug resource extent）。
- GPU：NVIDIA GeForce RTX 4060 Laptop GPU。
- 输出：`1280x720`；RR：`--denoiser dlss-rr`；上采样：`--upscaler dlss-quality`，实际渲染尺寸 `853x480`。
- 未运行 600/1800 秒测试；只运行 1 秒 benchmark、121/122 SPP 定点 capture 和 1 秒动画 smoke。
- PNG、benchmark raw JSON 和 stderr 位于已忽略的 `output/codex-fix-rr-boundary/`，不提交生成物。

## 2. 修复后的契约

- 边界 mask 覆盖真实边界两侧各两个输出像素，以包含 RR 重建邻域；连续 miss 区域仍不被整片标记。
- 非边界像素继续精确透传当前 RR HDR，不做全屏时域混合。
- 静止边界使用最多 128 帧的有界历史；运动大于 0.01 输出像素时降到 32 帧，大于 0.5 像素时降到 4 帧，大于 2 像素拒绝历史。
- 颜色 clamp 仍限定在相同 stable surface ID 内。仅在 ID、normal、depth、motion 都证明表面静止时放宽 YCoCg 包围盒，避免随机 RR 重建足迹逐帧拖动历史；移动时保持严格 clamp。
- ToneMap debug view 单独查询被显示资源的尺寸，不再把输出分辨率 t0 的尺寸误用于 render-resolution guide。

## 3. 可复现命令

最终画面在 121 和 122 SPP 各 capture 一次：

```powershell
.\target\release\ray_tracing_demo.exe `
  --output-size 1280x720 `
  --denoiser dlss-rr `
  --upscaler dlss-quality `
  --capture-output output\codex-fix-rr-boundary\final121.png `
  --capture-after-spp 121 `
  --debug-view final
```

122 SPP 只替换文件名和 `--capture-after-spp`。同样采集 `history-rejection`、`object-material-id` 和 `motion`。

右侧红墙/后墙接缝 ROI 明确为 `x=844, y=145, width=16, height=430`，即闭区间 `x=844..859, y=145..574`。它覆盖接缝两侧，不包含灯、地板和右侧方块。使用仓库内工具计算：

```powershell
.\target\release\image_diff.exe `
  output\codex-fix-rr-boundary\final121.png `
  output\codex-fix-rr-boundary\final122.png `
  --roi '844,145,16,430'
```

`image_diff` 的两参数旧用法保持兼容；增加的 ROI JSON 同时报告逐像素最大 RGB 通道差的均值和差值大于 2 的像素数。

## 6. 结论与剩余人工项

自动门槛通过。修复没有停止 jitter、冻结最终帧、跨 ID 插值或对整个画面增加时域滤波；它只稳定 RR 输出中被 stable primary visibility 证明为真实不透明边界的有限区域。

仍建议人工缓慢移动相机约 10 秒，观察接缝是否出现彩色拖尾；这是交互观感检查，不能由固定 capture 冒充。若该项通过，本工作包可以关闭。
