# 阶段 10 验收记录

更新时间：2026-08-10。目标设备：NVIDIA GeForce RTX 4060 Laptop GPU。

本记录只覆盖阶段 10 的 DLSS Super Resolution、DLAA、Reflex Low Latency 和 PCL
接入；没有实现 DLSS Ray Reconstruction、Frame Generation 或 Reflex 2 Frame Warp。
阶段 10 当前仍不能标记完成，但已不再被 Application ID 阻塞。仓库现在按 NVIDIA
DLSS Programming Guide 为自研引擎提供固定 GUID Project ID、`eCustom` Engine Type
和 Cargo package 派生的 Engine Version；数值 Application ID 仅作为 NVIDIA 明确
分配后的可选覆盖。目标机上的 DLAA、DLSS Quality/Balanced/Performance 以及
DLSS Quality+NRD 已分别通过 1 秒 Release 短测。剩余项目是 Debug GPU Validation、
真实窗口交互/画质观察和外部 Reflex 工具证据。

## Codex Review 修复（2026-08-10）

Review 后修正了以下接入问题：

- Streamline bridge ABI 升级为 v3，支持 NVIDIA 分配的数值 `application_id`，也支持
  官方推荐给自研引擎的 Project ID + `eCustom` + Engine Version。仓库固定 Project ID
  为 `59083655-5525-475b-95a2-a904bcf8f4c0`，不是 temporary/fake Application ID。
- manual hooking 在 `slUpgradeInterface` 之前通过 `slGetNativeInterface` 判断是否已是
  proxy，不再把所有 `eErrorInvalidIntegration` 吞成成功。
- 移除每帧提前调用的 `slAllocateResources`，改由首次 `slEvaluateFeature` 按官方
  lazy-allocation 路径创建资源。v2.12.0 的显式 allocation API 不带 frame token、
  会查询 frame 0，与本项目的 frame-based tags 不兼容；旧 Debug result 25 正是
  该错序接入的结果，不是硬件限制。
- Native generation 不再创建 DLSS depth/motion；DXR shader 只在 DLSS Final 路径写入
  guides。feature-off 和 feature-on Native 不再支付两张 DLSS texture 的显存和
  UAV 写带宽。
- Bridge 增加构造失败 RAII shutdown；PCL `SimulationEnd` 移到动画 CPU 更新后。
- build 会对 lock 中所有 SDK/许可文件重算 SHA-256；fetch 额外校验 production
  DLL Authenticode 的 NVIDIA signer，并支持干净 clone 下自行创建 `external/`。
- `stage10_acceptance.ps1` 现在对 GPU Total/active DLSS pass、optimal extent、VRAM、
  idle wait、Reflex/PCL 计数和 Debug InfoQueue 执行机器可判定的硬门槛，并支持
  `-CaseName` 独立 case。`-StreamlineApplicationId` 只用于真实 NVIDIA 数值 ID 覆盖。

## NRD 镜面输入质量后续复验

阶段 10 的 Streamline/DLSS 接入未改变，但阶段 9 后端随后提升了路径输入质量：
Owen-Sobol 时域序列、bounded GGX VNDF v3、NRD 主表面 Bayer probabilistic lobe +
`AREA_3X3` hitT reconstruction，以及 specular-origin 后续面积光 4-sample 预算。

同一 RTX 4060 Laptop、DLSS Quality + NRD 的新 1 秒直接 benchmark 为 Total p50/p95
`5.57/6.35 ms`、Path Trace `2.76/3.39 ms`、NRD Denoise `1.07/1.48 ms`、DLSS Evaluate
`1.25/1.65 ms`，idle wait 0。相对上表旧 `4.10/4.56 ms` 的 Total，新增画质预算有明确
成本，但仍远低于 `16.67 ms` 门槛；不得把旧数字继续当作当前可执行文件性能。
