# 阶段 8G：总体验收与债务收口执行方案

## 1. 基线、结论与交付边界

- 方案日期：2026-08-09。
- 目标硬件：NVIDIA GeForce RTX 4060 Laptop GPU。
- 代码基线：`2031abf`（阶段 8E-2 首轮 review 修复完成）。
- 当前状态：**8G 实现已完成并经 Codex review 修复；本文保留为原始实现规格，不再作为 Luna 的下一轮执行指令。修复后短矩阵复验见 [`阶段8G修复后短矩阵复验执行方案.md`](阶段8G修复后短矩阵复验执行方案.md)。**
- 本包目标：补齐可重复验收能力，执行阶段 8 最终矩阵，关闭能够在当前机器和仓库内关闭的历史债务，并诚实记录外部依赖。
- 本包不是新的渲染算法阶段：不得修改 Path Trace、随机采样、Temporal、À-Trous、ToneMap 或动态分辨率决策公式。

阶段 8F 本轮不实施。最新完整的 1920×1080 optimized 固定尺寸数据中，Path Trace p50/Total p50 为 `2.82/6.46 = 43.7%`，低于 8F 的 45% 入口；阶段 8E-2 默认动态三次 30 秒 Total p95 又只有约 7.4 ms，距离 16.67 ms 硬线有充足余量。不得为了继续写新功能而绕过该门槛。

8G 的正确交付不是“所有表格都写通过”，而是：

1. 自动化能证明的项目有机器可复核证据。
2. 必须人工观察的项目明确写人工结论和观察者，不能由 CLI 成功代替。
3. 缺少 PIX 程序、公开 PBR 资产或代表性大模型时，保持对应项未完成，不能伪造数据、降低门槛或把小三角形称作大 BLAS。
4. 只有所有阶段 8 硬门槛真正满足，才能把主方案的阶段 8 改为完成；否则状态应是“代码完成，仍有列明的验收债务”。

## 3. 工作包 8G-1：确定性实时截图与视图选择

### 3.1 CLI 契约

增加以下实时模式参数：

```text
--capture-output <PNG路径>
--capture-after-spp <1..4096>       默认 128，仅在 capture 模式合法
--debug-view <名称>                 默认 final
```

`--debug-view` 支持且只支持下列稳定名称，顺序必须与 F1 完全一致：

```text
final
raw
albedo
normal-roughness
depth
motion
variance
history-rejection
history-length
object-material-id
specular-hit-distance
```

约束：

- `--capture-output` 与 `--benchmark-seconds` 互斥，避免污染 benchmark stdout 和 GPU 时间边界。
- `--capture-after-spp` 没有 `--capture-output` 时必须报错；所有非有限、零、负数、越界和缺值输入必须报错。
- capture 可与固定或 dynamic 分辨率一起使用；像素相等 A/B 只能使用固定分辨率。
- 目标 PNG 已存在时必须拒绝覆盖。runner 每次创建唯一 `run-id` 目录，不能靠删除旧证据解决冲突。
- capture 成功后 stdout 只输出一行 capture JSON，并正常退出；失败必须返回非零退出码且不得留下被当作成功图的半文件。
- capture JSON 至少包含：schema/version、PNG 相对或用户传入路径、GPU 名称、output/render extent、requested scale、resolution mode、debug view 名称/索引、实际 SPP、frame index、generation id、三个 mode 和 PNG 字节数。

### 3.2 统一 DebugView 类型

把裸 `u32 debug_view` 收敛成一个有界 `DebugView` 类型：

- 负责 CLI name/index 映射、HLSL root constant、中文标题和 F1 `next()`。
- 枚举到 HLSL 数值的映射必须有覆盖全部 11 项的单元测试。
- F1 每次切换后向 stderr 输出稳定行，例如 `debug_view_changed index=1 name=raw`。
- fixed F2 每次真实切换输出 old/new requested scale、old/new extent 和 generation；dynamic F2 继续输出“由 GPU 控制、不可手动切换”，并使用稳定前缀。
- resize/minimize/restore 完成后输出 output/render extent、generation、history reset 和 resize 导致的 idle wait；日志只用于验收，不得改变行为。

命令行直接选择视图证明的是“11 个 shader 视图可渲染”，不证明 F1 键盘输入。F1/F2 的实际输入仍须在交互矩阵中单独验证。

### 3.3 D3D12 readback 生命周期

截图源必须是 ToneMap 后的 `display_output`（`R8G8B8A8_UNORM`），不能截桌面窗口、标题栏或被 DPI 缩放后的 OS 表面。

实现顺序：

1. 只在 capture 请求达到目标 SPP 的那一帧创建或使用一次性 readback buffer。
2. 使用 `GetCopyableFootprints` 取得 row pitch 和总大小；禁止假设 `width * 4` 已满足 D3D12 对齐。
3. `display_output` 已处于 `COPY_SOURCE` 时，在 Total timestamp 和 PIX Total event 结束之后调用一次 `CopyTextureRegion` 到 readback buffer，再把 display output 恢复为 UAV。
4. capture copy 不得进入 Total/各 pass 统计，也不得改变正常 swap-chain copy。
5. 提交后把 readback、footprint、尺寸、目标路径和本帧 fence 保存为 pending capture。不得立即 `wait_for_gpu()`，不得添加每帧 stall。
6. 后续事件循环只在 `fence.GetCompletedValue() >= capture_fence` 后 Map；逐行剥离 padding，得到紧密 RGBA8，再保存 PNG。
7. 允许创建尚不存在的父目录；文件先写同目录唯一临时名，成功后原子 rename 到目标名；只能清理由本次 capture 创建的临时文件。
8. PNG 和 JSON 完成后再退出。readback 必须活到 fence 完成；resize 或关闭不能提前释放仍在飞行的资源。

建议把 CPU 侧的 row-pitch 剥离和 capture JSON 组装写成纯函数，分别测试：正常 padding、无 padding、长度不足、宽高溢出、fixed/dynamic metadata。不能通过等待整个 GPU 空闲来简化生命周期。

### 3.4 PNG diff 工具

增加 `src/bin/image_diff.rs`，复用已有 `image` 依赖；同时在 `Cargo.toml` 设置 `default-run = "ray_tracing_demo"`，避免新增 binary 后破坏现有 `cargo run --release -- ...` 用法：

```text
cargo run --release --bin image_diff -- <actual.png> <expected.png>
```

输出单行 JSON：宽高、RGB changed pixel 数、alpha mismatch 数、最大通道绝对差、MAE、RMSE。尺寸/格式不兼容必须非零退出。不要引入新的图像或哈希依赖；SHA-256 由 PowerShell `Get-FileHash` 记录。

门槛：

- 8C command-recording baseline/optimized 的 11 个 fixed A/B 必须逐像素完全相同。
- 8D static AS baseline/optimized 的 11 个 fixed A/B 必须逐像素完全相同。
- 8B baseline/shared 的 fixed final 图允许 `max_abs <= 1` 且以 8-bit 通道值计 `RMSE <= 0.10`；超出就记录 retained experiment correctness failure，但不得切换默认。
- dynamic 与 fixed、不同内部尺寸、动画或不同 SPP 的图不得使用 exact 门槛。

### 3.5 8G-1 测试

- CLI 成功、未知 view、缺值、非法 SPP、capture/benchmark 冲突、已有目标文件。
- 11 项 DebugView name/index/next 循环。
- footprint/row-pitch 纯函数。
- capture JSON fixed/dynamic 字段。
- image diff 的 identical、单通道差异、alpha 差异、尺寸不符。
- Release capture smoke：1280×720、fixed 1.0、final、128 SPP；PNG 必须正好 1280×720，进程自动退出。
- Debug + GPU-Based Validation capture smoke：正常退出，InfoQueue 0 条消息。

## 4. 工作包 8G-2：显存测量区间与自动验收 runner

### 4.1 显存 measurement 语义

现有 JSON 只有 benchmark 结束时的 local usage，无法证明 30 分钟内没有阶梯增长。为 `VideoMemoryTelemetry` 增加与 `begin_benchmark_measurement()` 对齐的 bounded measurement：

- `start_usage_bytes`
- `end_usage_bytes`
- `peak_usage_bytes`
- `minimum_budget_bytes`
- `peak_usage_ratio`
- `valid_query_count`
- `failed_query_count`
- 最多 60 个按 60 秒采样的 `{elapsed_seconds, usage_bytes, budget_bytes}` checkpoint

要求：

- warm-up 不进入 measurement；begin 时强制查询一次并重置上述字段。
- 之后沿用约 500 ms 的已有查询频率，不为遥测增加 GPU wait。
- 查询失败必须计数，不能把失败值当零，也不能用一次失败抹掉前一有效 `end`。
- `benchmark_json.memory` 保留现有兼容字段，并新增 `measurement` 对象。
- benchmark 最大 3600 秒，因此 checkpoint 必须有固定上界；禁止保存每帧或每 500 ms 的无限 Vec。
- 为 start/end/peak/min budget、失败查询、60 项容量上限和 epoch reset 写纯单元测试。

### 4.2 PowerShell runner

新增 `scripts/stage8_acceptance.ps1`，至少接受：

```text
-Configuration Debug|Release
-Exe <可执行文件>
-OutputRoot <目录，默认 output/stage8g>
-Runs <默认 3>
-Seconds <默认 30>
-LongRunSeconds <默认 1800>
-LargeModel <可选外部 glTF 路径>
-PbrModel <可选外部 Khronos glTF 路径>
-SkipLongRun
-SkipCaptures
```

runner 必须：

1. 为每次执行创建唯一目录并保存 stdout、stderr、退出码、命令参数和原始 JSON；不能依赖屏幕抓取。
2. 从 stdout 的最后一个非空行解析 JSON，同时验证 stdout 没有额外业务文本破坏单行契约。
3. 保存环境摘要：当前 commit、GPU 名称、驱动版本、活动 Windows 电源方案、是否检测到电池/AC。拿不到的字段写 `N/A`，不得猜测。
4. 对三次运行分别保留原始值，并另算三次中位数；不能只保存最优一次。
5. 自动检查 JSON 的有限数、样本数、mode、extent、counter 守恒和门槛；任何失败使脚本非零退出，并在 summary 中列出具体字段。
6. 只写 `output/`；不自动 `git add`、不下载资产、不启动/安装 PIX、不触碰仓库外文件。
7. 长测前先完成同参数 30 秒 smoke；smoke 失败时不得继续浪费 30 分钟。

### 4.3 自动对账规则

每个 benchmark 至少检查：

- `passes.total.valid_samples > 0`，所有 p50/p95 为有限非负数，且 p95 不小于 p50。
- fixed measurement 的 generation create/switch/retired、extent change、history reset 和 idle wait 均为 0。
- dynamic：`passes.total.valid_samples = dynamic.measurement.valid_samples + stale_generation_samples_ignored`。
- dynamic：measurement `switch_count = downscale_count + upscale_count`。
- 没有 output resize 的 dynamic：generation create/switch 均等于 dynamic measurement switch；generation retired 最终应追平 switch，`retired_generation_count=0`、high-watermark 不超过 2、`gpu_idle_wait_count=0`。
- 最终 output extent 必须等于命令指定值；否则该运行被 resize 污染，只能保留作诊断，不能进入性能汇总。
- local peak usage/budget 小于 70%；长测 checkpoints 不得出现无法回落的持续单调阶梯增长。
- `pix_events_available=true` 只证明 instrumentation DLL 加载成功，不证明 PIX UI 已安装或 capture 已抓取。

## 5. 工作包 8G-3：RTX 4060 Laptop 最终执行矩阵

所有性能运行使用 Release、插电、关闭其他重 GPU 程序，并显式固定：

```text
--atrous-mode baseline
--command-recording-mode optimized
--acceleration-structure-mode baseline
```

### 5.1 性能和生命周期

| 场景 | 次数/时长 | 必须记录 |
| --- | --- | --- |
| Cornell fixed 1280×720、1600×900、1920×1080，scale 1.0 | 每档 3×30 秒 | 全 pass、CPU、命令记录、显存 measurement |
| Cornell fixed 1920×1080，scale 0.83/0.75/0.67 | 每档 1×30 秒 | output/render extent、Total、history/generation/idle |
| Cornell dynamic 1920×1080，target 14.5 ms | 3×30 秒 | p50/p95、范围、switch/stale、显存 |
| Cornell dynamic 1920×1080，target 4.0 ms | 先 1×30 秒，再 1×1800 秒 | 降档、generation 退休、idle 0、显存 checkpoint |
| 现有静态 glTF 和动画 glTF | baseline/optimized AS 各 1×30 秒 | AS/Path/Total、策略计数、动画 history |
| 代表性大静态 glTF（若提供） | baseline/optimized AS 各 3×30 秒 | compact copy、allocation 节省、画面和性能门槛 |

硬门槛：

- 默认 1080p 三次 Total p95 全部 `<= 16.67 ms`。
- 8G 没有渲染算法改动，1080p 三次中位 Total p95 相比当前约 7.44 ms 不应回退超过 3%；若首次失败，先确认温度、电源、后台负载并完整重跑，不得挑单次数据。
- dynamic 切换平均频率不超过 1 次/秒，不出现相邻两档持续往返。
- 长测满足第 4.3 节所有 counter/显存条件，且没有 Device Removed、panic 或 output resize 污染。
- 大模型缺失时 AS 默认保持 baseline；即使有模型，也只有原 8D 的全部采纳门槛满足才能改变默认。

### 5.2 确定性截图矩阵

统一使用 1280×720、fixed 1.0、128 SPP：

1. command baseline/optimized：11 个 debug views，两两 exact。
2. AS baseline/optimized：现有静态 `NonIndexedMultiNode.gltf` 的 11 个 views，两两 exact。
3. À-Trous baseline/shared：final 一对，使用第 3.4 节容差。
4. fixed 1.0/0.83/0.75/0.67：各保存 final，人工检查灯边光晕、几何边缘、运动/历史重置伪影；不同尺寸间不做 exact diff。
5. dynamic 14.5 和强制 4.0：稳定后各保存 final 和 history-rejection；只作人工尺寸切换伪影证据。

### 5.3 Debug + GPU-Based Validation

至少覆盖：

- Cornell fixed baseline/optimized command recording。
- Cornell dynamic 默认和强制降档。
- static/animated glTF 的 AS baseline/optimized。
- 一次 capture readback。
- resize 1280×720 → 1600×900 → 1920×1080 → 1280×720；最小化/恢复；shader hot reload。

全部应正常退出，InfoQueue 0 条消息，不得出现 resource state、readback footprint、descriptor lifetime、AS source lifetime、fence、device removed 或 shader reload 后旧资源错误。

### 5.4 必须人工确认的项目

Luna 可以准备窗口、日志和截图，但以下项目没有真实观察就不能写通过：

- 实际按 F1 连续 11 次再回到 final；stderr 顺序应完整，窗口标题/画面同步变化。
- fixed 模式按 F2 走 `1.00 → 0.83 → 0.75 → 0.67 → 1.00`；dynamic 模式按 F2 不得切换并给出明确提示。
- resize、最小化/恢复、hot reload 后画面继续更新，无黑屏、拉伸残影或永久噪点跳变。
- 公开 PBR 资产的 base color、法线方向、roughness/metallic 和 UV 朝向。
- fixed 各档和 dynamic 稳态截图中，灯四周、箱体边缘、镜面和阴影没有新增鬼影或尺寸切换残影。低 SPP 随机噪声本身不等于回退，判断重点是结构化残影和历史错误。

如果 Luna 无法做可信视觉观察，应把图片和操作步骤留在 `output/stage8g/`，并在报告中写“等待用户/Codex 人工确认”，不能替用户作结论。

### 5.5 外部资产和 PIX

- 优先由用户提供 Khronos Sample Assets 中可合法加载的 PBR/大模型路径；可选候选为 Damaged Helmet 一类具有纹理和较大单 BLAS 的官方示例。
- 不得提交下载资产。记录资产名称、上游 URL、commit/tag 或获取日期、license、文件哈希、primitive/triangle 数；若 loader 不能读，记录真实错误。
- 可以用生成的大网格只覆盖 compact-copy 机械分支，但它不能替代公开 PBR 画质验收，也不能自动满足“代表性大模型”采纳门槛。
- `WinPixEventRuntime.dll` 只是插入 PIX event 的运行库，不是 PIX GUI/capture 工具。只有机器已有 Microsoft PIX 且 Luna 能正常操作时才抓两份 capture；否则记录 `PIX UI unavailable`，不要安装软件或制造空 capture 文件。

```text
docs(stage8): record final acceptance results and remaining debt
```

禁止把全部代码、30 分钟数据和文档压成一个无法 review 的提交；禁止提交中间不能构建的状态；禁止改写或 squash 既有历史。

## 8. 每个提交与最终交付的检查

每个代码提交：

```text
cargo fmt --all -- --check
cargo test --all-targets
cargo clippy --all-targets --all-features -- -D warnings
cargo build
cargo build --release
git diff --check
```

最终交付必须列出：

- commit hash/message 和修改文件。
- 实际执行过的命令、耗时、退出码。
- 未执行项及原因，尤其是人工视觉、外部资产、PIX 和 1800 秒长测。
- `output/stage8g/<run-id>/summary.json` 的位置，但不要把绝对用户路径写进提交文档。
- 建议 Codex 优先 review 的高风险点：capture fence/readback 生命周期、Total 边界、row pitch、measurement epoch、runner 是否挑数据、状态是否提前宣布完成。
