# 阶段 11：RR 玻璃透射稳定修复记录

日期：2026-08-13

目标 GPU：NVIDIA GeForce RTX 4060 Laptop GPU

## 1. 现象与根因

右侧玻璃箱内部显示的是经过玻璃前、后界面折射后命中的墙面或地板，不是普通镜面反射。
原 RR 路径每帧按 Fresnel 概率随机选择反射或折射，且输出分辨率稳定 pass 只认识相机首先
命中的玻璃界面。即使相机和场景完全静止，RR 收到的玻璃 radiance 及其隐藏表面身份仍会
随帧变化，因此内部像会呈现水波纹式抽动。

玻璃底面与地板也不能作为两个独立、完全共面的三角形保留。两者拥有不同 primitive、
material 和介质语义，但交点距离相同；DXR 遍历没有“应选哪一个”的业务规则，浮点误差
还会使命中在两者间切换。当前场景把隐藏底面轻微埋入地板，稳定 guide 进一步把光线在
玻璃内部首先遇到的非玻璃接触面视为主透射命中，避免虚构位于地板之后的第二个可见界面。

## 2. 最佳实践依据

- [DLSS-RR Programming Guide](https://github.com/NVIDIAGameWorks/Streamline/blob/main/docs/ProgrammingGuideDLSS_RR.md)
  要求为反射/透明效果提供与其实际图像对应的 guide；`TransparencyLayer` 是预乘 Alpha
  的独立合成层，`ColorBeforeTransparency` 主要用于透明粒子消失或拖影。
- [NVIDIA NRD](https://github.com/NVIDIA-RTX/NRD) 明确说明 NRD 并非原生面向透明/体积信号；
  其 sample 对玻璃采用可重投影的已降噪画面，而不是把原始透明路径直接交给降噪器猜测。
- [RTXPT](https://github.com/NVIDIA-RTX/RTXPT) 采用路径空间分层和匹配的 guide buffer 生成，
  即先确定信号属于哪个可重投影表面，再进行时域重建。

本项目实测过把原始玻璃 HDR 直接提交为 RR `TransparencyLayer`：接口能正常运行，但该层
不会替应用把原始路径追踪透明信号降噪，玻璃下部反而出现明显白色散斑，因此没有保留。
本轮采用更适合小型渲染器的直接实现：降低输入方差，再为主透射命中建立稳定虚拟表面。

## 3. 实现契约

1. RR 与 NRD 都对相机可见玻璃同时追踪主反射和主透射，不再做逐帧 Bernoulli Fresnel
   分支；嵌套深度仍受限，避免指数级路径增长。
2. RR 的 noisy HDR 保留完整玻璃颜色，让 RR 继续重建并超分该信号；不重复提交透明层，
   因而不会重复增亮，也不会旁路 RR 输出原始雪花。
3. RR 的 output-resolution、无 jitter visibility pass 对静止玻璃追踪主透射：
   - 玻璃内部首先命中不透明接触面时，直接使用该面；
   - 首先命中玻璃出口时，按 IOR 再折射一次并追踪下一个不透明表面；
   - 输出透射表面的 stable ID、法线和前后帧 view-Z，并使用虚拟 ID 命名空间。
4. 相机与玻璃都静止时，折射虚拟表面的输出像素运动严格为零。现有 RR 有界历史只在该
   虚拟表面及真实边界累积；普通像素仍精确透传 RR 输出，不增加全屏模糊。
5. TIR、无效命中、嵌套玻璃、相机运动或玻璃动画均保守回退到物理首表面，不能制造
   看似稳定但重投影错误的 guide。

## 5. 范围与后续

当前实现针对一个静态、封闭的 legacy dielectric 及其主透射路径，符合 Cornell 场景的
实时成本预算。若以后加入运动玻璃、曲面多层玻璃、液体或嵌套介质，应扩展为显式的前后帧
界面变换、介质栈和独立路径层；不能简单放宽当前静态门槛或扩大全屏历史。
