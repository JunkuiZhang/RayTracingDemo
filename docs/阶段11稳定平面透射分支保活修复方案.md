# 阶段 11 稳定平面透射分支保活修复方案

## 1. 目标与边界

修复 stable-plane Build 在闭合玻璃和 nested dielectric 中优先丢掉高能透射分支的问题，使
Cornell 玻璃和 nested 内层液体不再因分支调度而变黑，同时保持以下约束：

- 最多 3 个 stable planes，不增加显存层数；
- 分支暂存仍是固定上限，不分配动态 GPU 内存；
- 分支选择跨像素确定，不按吞吐量大小动态重排，避免空间接缝；
- 不修改 NRD、Streamline、曝光或材质参数来掩盖 Build 错误；
- 默认 `--path-space-mode` 仍为 `legacy`；不顺带实现 ReSTIR、FG 或 `auto` 切换；
- 验收只跑短时 Smoke、约 30 秒 Quality 和 1 秒 benchmark，不跑长时测试。

建议拆成两个提交，不要把 shader 行为和 runner 证据混在一个提交中。

## 2. 已确认的根因

当前 `shaders/stage11_stable_plane_build.hlsl` 使用长度为 6 的数组和单调递增 `tail`：

1. 玻璃界面总是先 `EnqueueBranch(reflected)`，再 `EnqueueBranch(transmitted)`；
2. `head` 消费过的数组槽位不复用，`tail == 6` 后所有新分支都被拒绝；
3. nested 外玻璃/内液体有多次 Enter/Exit，主透射链尚未抵达后墙就可能被拒绝；
4. `EnqueueBranch` 先检查容量、后检查 `1e-5` 阈值，导致本应属于主动低能裁剪的分支也被记作
   queue overflow，与阶段 11 counter 定义不一致；
5. 首轮 nested benchmark 因而记录 NRD 19,470,489、RR 9,819,681 次 queue overflow，内层液体
   在两条 consumer 中都近乎纯黑；介质 overflow/invalid exit 为 0，排除了 interior-list 硬错误。

不要使用“把 6 改为 12/16”作为修复。它只推迟相同错误，增加每线程寄存器压力，也无法保证主
透射链先完成。

## 3. RTXPT 对照结论

官方 RTXPT 将稳定平面 Build 作为独立的 delta-path exploration；遇到分叉时，把额外 lobe 写入
可用 plane 的 exploration start，并让当前路径沿一个固定 lobe 继续。它没有按每像素瞬时吞吐量
重排 lobe；源码还明确说明这种排序会令相邻像素选择不同分支，阻断 denoiser 的空间共享并形成
接缝。

参考：

- [RTXPT 项目与 path-space layer decomposition](https://github.com/NVIDIA-RTX/RTXPT)
- [PathTracerStablePlanes：固定 lobe 顺序、available planes 与 current-path reuse](https://github.com/NVIDIA-RTX/RTXPT/blob/main/Rtxpt/Shaders/PathTracer/PathTracerStablePlanes.hlsli#L1425-L1579)
- [NVIDIA GTC：stable pass 探索镜面反射/折射并分别生成 denoising planes](https://www.nvidia.com/en-us/on-demand/session/gtcspring23-s51871/)

本项目不需要照搬 RTXPT 的完整 payload/plane scheduler；采用等价的小型策略即可：**当前路径
固定沿 transmission 继续，reflection 作为有界 fork 入队；mirror/TIR 只有一个有效 lobe，直接
原地继续。** 这是材质拓扑决定的稳定顺序，不是随吞吐量变化的排序。

## 4. 提交一：修复 Build 分支调度

建议提交：

```text
fix(stage11): preserve stable transmission continuation
```

### 4.1 `EnqueueBranch` 计数语义

在 `shaders/stage11_stable_plane_build.hlsl` 中先判断低能阈值，再判断容量：

```hlsl
if (AverageThroughput(branch.throughput) < 1.0e-5)
    return false;
if (tail >= MAX_BUILD_QUEUE)
{
    InterlockedAdd(...BRANCH_QUEUE_OVERFLOW, 1u);
    return false;
}
```

低能主动裁剪不能增加 queue overflow。保留 bool 返回值；本提交不增加新的全局 counter。

### 4.2 单 lobe 必须原地继续

- mirror：构造 `reflected` 后令 `state = reflected`，继续当前 `MAX_BUILD_STEPS` 循环；不要入队后
  `break`；
- TIR：同样令 `state = reflected` 并继续，不占 fork queue；
- transmission 的 medium update 无效或 branch ID 达到上限时，不得产生伪透射；按现有硬错误语义
  结束或沿唯一合法反射继续，不能清空/伪造 interior slots。

### 4.3 dielectric 固定 continuation

非 TIR 且 medium update 有效时：

1. 按现有 branch ID 规则构造 reflection 和 transmission；
2. reflection 是额外 fork，调用 `EnqueueBranch`；
3. transmission 复用当前执行槽：`state = transmitted; continue;`；
4. 不再把 transmission 入队；
5. 不比较 Fresnel/throughput 来决定哪一支 continuation，也不在不同像素动态交换顺序。

代码旁必须写明：固定 transmission continuation 是为了保持闭合介质的主链和跨像素分支身份；
不能改成 throughput sort，因为那会在 Fresnel 交叉处产生 plane identity 接缝。

### 4.4 有界性

必须继续依赖现有三重边界：

- 每个 branch 最多 `MAX_BUILD_STEPS == 16`；
- branch ID 最多 `MAX_STABLE_DELTA_VERTICES == 15`；
- fork 数组最多 `MAX_BUILD_QUEUE == 6`。

禁止改成无界 ring queue。消费槽复用会允许远多于 6 个 fork 被依次生成，扩大最坏执行时间；本轮
只需保证当前 continuation 不占 fork queue。

## 5. 提交二：回归模型与可重放证据

建议提交：

```text
test(stage11): gate nested transmission retention
```

### 5.1 CPU 调度参考测试

在 `src/path_space.rs` 增加仅供测试的小型 deterministic scheduler/reference，不复制 HLSL 光追，
只模拟 lobe 调度。至少覆盖：

- outer glass → inner liquid → inner exit → outer exit 的四段 transmission continuation 能到达 base；
- 每个普通 dielectric junction 只向 fork queue 增加 reflection；
- mirror 和 TIR 原地继续，不增加 fork 数；
- 小于 `1e-5` 的 fork 被主动裁剪且 overflow 保持 0；
- 固定容量已满时只拒绝额外 fork，不能令 current transmission 消失；
- 同一拓扑在不同 Fresnel 权重下产生相同 continuation branch/lobe 序列。

测试名称应表达行为，不要只用 `shader_contains("continue")` 作为唯一保护。可以保留一项轻量 HLSL
契约检查，锁定 threshold-before-capacity 的计数顺序，但核心正确性必须由结构化 CPU 模型验证。

### 5.2 Quality nested benchmark 证据

修复 `scripts/stage11_stable_planes_acceptance.ps1`：nested NRD/RR 的 128 SPP capture 完成后，各追加
一次 1 秒 benchmark，并复用 `Test-BenchmarkContract`。原始 JSON 必须进入该 run 的
`process_records`，避免像首轮补充诊断那样只有控制台摘要。

Quality 仍保持人工画质 `PENDING_MANUAL`；自动契约只硬判：

- process/JSON/pass/counter 合法；
- `interior_overflow_events == 0`；
- `invalid_medium_exit_events == 0`；
- `gpu_idle_wait_count == 0`。

首轮不把 queue overflow 强制为 0，但必须在修复前后记录总数、每完成帧均值及相对
`pixels_traced` 的比率。不能仅展示下降百分比而隐藏绝对值。

### 5.3 SelfTest

SelfTest 增加：

- nested Quality case 确实带 1 秒 benchmark；
- benchmark 缺 counter 时拒绝；
- nested capture PASS 但 benchmark FAIL 时 suite 总体必须 FAIL；
- `PENDING_MANUAL` 仍不能汇总成 PASS。

## 6. 验证顺序与停止条件

按顺序执行，前一步失败就停止，不继续 Gate：

```powershell
cargo test --all-targets --locked
cargo test --all-targets --features nrd --locked
cargo test --all-targets --features streamline-rr --locked
cargo test --all-targets --features nrd,streamline-rr --locked
.\scripts\stage11_stable_planes_acceptance.ps1 -SelfTest
```

随后重新构建隔离 NRD/RR Release，运行：

```powershell
.\scripts\stage11_stable_planes_acceptance.ps1 `
  -Suite Smoke `
  -NrdExe <new-nrd-exe> `
  -RrExe <new-rr-exe> `
  -TimeoutSeconds 30

.\scripts\stage11_stable_planes_acceptance.ps1 `
  -Suite Quality `
  -NrdExe <new-nrd-exe> `
  -RrExe <new-rr-exe> `
  -TimeoutSeconds 60
```

通过条件：

- Smoke 自动 PASS；Quality 自动证据无 FAIL、总体为 `PENDING_MANUAL`；
- nested 内层液体不再是边界整齐的纯黑块，能看到透射后的场景与合理吸收色；
- Cornell 玻璃不能发生新的黑块、漏光或 plane-identity 接缝；
- NRD/RR nested benchmark 的两个介质硬错误保持 0；
- current transmission 不再因 fork queue 满而丢失；
- 记录 queue overflow 修复前后数据，不用扩大容量制造表面下降；
- 不运行 600/1800 秒测试。

通过后由 Codex review 提交与 raw evidence，再进入 Lifecycle；不要在这个修复中提前执行默认
`auto` 切换。
